# Demonstration learning and bounded policy execution

The supplied Bracket Bot summaries support dual-arm teleoperation and a collect/train/deploy workflow. They do not provide a production Quest stream, verified observation/action API, calibration or an autonomous trained policy. This implementation therefore makes the **learning lifecycle runnable**, while keeping real robot VLA deployment blocked.

## Implemented lifecycle

`ml.pipeline.LearningPipeline` provides persisted session creation, recording, stopping, labeling, review, governed JSONL export, policy registration, actual tiny-model training, heldout evaluation, synthetic research activation, retirement and rollback. The gateway applies role authentication; the registry records lifecycle events. The JSON registry uses atomic replacement and a process-local lock; run one writer process. It is a local research store, not a distributed model registry or encrypted media service.

Sessions require explicit consent and a synthetic/approved mock environment. Patient data capture is rejected. Frames require head RGB/depth and both wrist references, base pose/velocity and localization confidence, both seven-joint arm states/velocities, lift/grippers, action, intervention marker, failure category and safety events. Stream timestamps must be within 30 ms of the frame, and frame timestamps must strictly increase. These thresholds are synthetic dataset-contract assumptions, not measured vendor synchronization guarantees.

Frames store opaque media references; the pipeline does not fetch media. The bundled synthetic demo uses `synthetic://no-media/...` references and contains **no camera pixels or real robot observations**. A recording adapter must later produce verified media, timestamps and hashes. The current synthetic action schema is a 3D delta limited to 2 cm per proposal. It is not a Bracket Bot action interface.

Review requires stopped, nonempty, labeled episodes and explicit privacy/safety clearance by a named reviewer. Reviewed episodes cannot be relabeled in place. Dataset export additionally requires explicit human approval. Failure and corrective episodes remain in the registry for analysis rather than being silently removed.

## Run the actual learning demonstration

```powershell
.\.venv\Scripts\python.exe -m ml demo --output ml/outputs --seed 17
```

The command generates five synthetic episodes with 60 frames and simulated correction markers, fits a ridge behavior-cloning policy on 48 frames, holds out the fifth episode's 12 frames, and computes action error and bound violations. It also runs MuJoCo software regressions and deterministic abstention fixtures. The demo writes a registry, artifact hash and `demo_report.json`.

This is a **small state-feature linear regression experiment**, not a vision-language-action model. Its labels are generated by a simple synthetic linear controller; low regression error only shows that this pipeline fits that mapping. It does not establish visual grounding, language understanding, grasp skill, recovery competence or hospital generalization. The deterministic safety filter owns abstention; the tiny model did not learn it. MuJoCo regression tests are separate software checks and do not simulate the trained policy accomplishing a manipulation task.

The artifact is left `simulator_evaluated`; the demo does not invent human safety approval. Research activation requires an explicit named signoff through `promote_policy`. Production/hardware promotion is rejected even if the caller submits apparently successful metrics. Imported policy metadata cannot supply authoritative scores: evaluation requires a locally generated supported artifact with a matching content hash. Retired versions cannot execute, and rollback revalidates the previous artifact's integrity and eligibility.

`propose_action` checks active research status, synthetic environment, a 100 ms maximum horizon, allowlisted object class, identity/grasp confidence, cleared attachment, conservative synthetic mass/clearance limits and distribution before returning a bounded proposal. It emits `requires_external_safety_approval=true` and never controls motors. The independent runtime safety supervisor still owns E-stop/watchdog, current room policy and every execution veto.

The complete frame JSON schema is exportable with `TeleopFrame.model_json_schema()`. `list_skills()` exposes benchmark A-F definitions and honest null rates. `route_skill` returns blocked, deterministic, a synthetic feature-policy proposal or a disconnected teleoperation fallback, based on the current envelope. No validated foundation-model VLA is installed.

## Path to a real bounded VLA

Obtain the verified vendor action/observation contract first, then collect consented mock-room multi-view trajectories from actual Quest teleoperation with common clock/calibration, split by object instance/operator/layout, and train an embodiment-compatible policy. The [OpenVLA project](https://openvla.github.io/) and [official training repository](https://github.com/openvla/openvla) provide one concrete research reference for adaptation, not evidence of drop-in compatibility with the new Bracket Bot. Check current supported action representations, compute requirements and data/model licenses before choosing a framework.

Require heldout object/layout benchmarks, negative/no-action cases, collision/contact and intervention metrics, independent outcome verification, deterministic simulator envelopes, supervised lab rollouts and real robot model verification. Bimanual bags and especially clean fabric need real demonstrations and task-specific lab evaluation. Shared H100 access described in supplied material remains unprovisioned here. Hardware SDK, Quest connection, base/arm/lift/gripper action mapping, pretrained VLA training, real camera data and lab trials remain unavailable.
